# Code of Conduct

## TL;DR

Be respectful. Engage with arguments and code, not with people. Remember that
this project's central conclusion is **negative** (the strategies don't
work) — please discuss the methodology and findings, not the author's
character or intelligence.

If you can't engage civilly, please don't engage at all.

---

## Scope

This Code applies to all project spaces:

- GitHub issues, PRs, and discussions on this repository
- GitHub Security Advisories
- Any community space (Discord / Slack / forum) hosted by the maintainers
- External venues when the participant is identifiably associated with
  this project (e.g., presenting the paper at a conference, posting on
  social media linking to the repo)

---

## Expected behavior

✅ Engage with substance: read the paper, check the data, then argue methodology.
✅ Cite specific lines or sections when disagreeing.
✅ Assume good faith; ask before assuming malice.
✅ Accept that the project is closed and will not be reopened to add new
   active strategies — argue the existing methodology if you disagree,
   not "you should have built X instead".
✅ Welcome newcomers — many readers will be retail traders who got here
   from a Medium post and have not read the paper.

## Unacceptable behavior

❌ Personal attacks on contributors, the author, or other commenters.
❌ Harassment of any kind (private messages, DMs, doxxing).
❌ Discrimination based on race, gender, sexual orientation, religion,
   nationality, age, disability, or any other identity characteristic.
❌ Bad-faith engagement designed to provoke rather than discuss.
❌ Promoting paid trading services or signal subscriptions in any project
   space. This is not the venue for sales.
❌ Trolling, including "ironic" trolling.
❌ Demanding that the author share specific trading P&L, account
   balances, or other private financial information.
❌ Use of slurs or hate speech.

---

## Specific notes for this project

This is a project that publishes a **negative result** about retail
algorithmic trading. As such it is likely to attract two opposite
audiences:

1. **Skeptics of retail algo trading** who want to use this as ammunition
   against trading communities. Please don't. The project's finding is
   specifically that *the strategy class tested* did not generalize, and
   that the *author's earlier in-sample claims* were inflated by bugs.
   It is not a claim that all retail traders are deluded.

2. **Defenders of retail algo trading** who want to argue the result is
   wrong. Please engage with the methodology specifically: walk-forward
   design, Deflated Sharpe, PBO, choice of universe. "But my strategy
   works" is not an argument against this paper unless you have similar
   multi-market walk-forward evidence.

Both audiences are welcome to engage. **Neither audience is welcome to
treat the author or each other badly.**

---

## Reporting

If you experience or witness unacceptable behavior:

1. **In a public space** (issue thread, PR comments): you can reply
   asking the person to stop, or escalate to maintainer if uncomfortable.
2. **For escalation**: open a GitHub Security Advisory (these are private)
   and label it `conduct`. Maintainer will respond within 7 days.
3. **For external behavior** identifiable to this project: include
   evidence (screenshots, links) in the Advisory.

We will not publicly identify reporters without their permission.

---

## Enforcement

Maintainer responses to confirmed Code violations:

| Severity | Response |
|---|---|
| Minor (one-time rude comment) | Private message asking the person to dial it back |
| Moderate (pattern of incivility, dismissiveness) | Public reminder of Code; temporary lockdown of the thread if needed |
| Serious (harassment, hate speech, doxxing) | Permanent ban from all project spaces; report to GitHub Trust & Safety |
| Severe (threats, real-world harm) | Immediate ban + report to relevant authorities |

Enforcement decisions are not negotiable, but bans can be appealed once
after 90 days via a brief written request to the maintainer.
